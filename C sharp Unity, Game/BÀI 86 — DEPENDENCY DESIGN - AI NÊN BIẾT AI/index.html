    5. Coupling là gì?

    Coupling = mức độ một phần code bị dính chặt vào phần khác.

    High coupling:

    A đổi
↓
B vỡ
↓
C phải sửa
↓
D cũng sửa

    Low coupling:

    A đổi
↓
mostly A

    6. Nhưng low coupling không có nghĩa mọi system không biết nhau

    Nếu cố cực đoan:

    không class nào được gọi class nào

    thì game cũng không chạy.

    Goal:

    Mỗi dependency phải có lý do rõ ràng.

    WeaponRuntime

    104. Simple solution

    using UnityEngine;

    MonoBehaviour

    private float speed =
        5f;


    public void Initialize(
        Transform target)
    {

            target;
    }


    private void Update()
    {
        if (target == null)
        {
            return;
        }


        transform.position =
            Vector3.MoveTowards(
                transform.position,
                target.position,
                speed *
                Time.deltaTime
            );
    }
}

    Instantiate(
        enemyPrefab

    118. BÀI 86 CẦN NHỚ GÌ?

    Dependency:

    A → B

    means A needs B somehow.

    Goal is not:

    zero dependencies

    Goal:

    clear dependencies
correct direction
coherent responsibility
low unnecessary coupling

    The five strongest questions:

    1. Why does A need B?
2. Should this dependency be direct or event-based?
3. Is the dependency explicit or hidden?
4. Who creates/wires these objects?
5. Does this dependency create a cycle or mix responsibilities?

    And the most important new idea:

    Đừng dùng interface/event/dependency injection vì chúng “trông kiến trúc”. Dùng chúng khi chúng làm boundary thật sự rõ hơn.

    Direct calls are good.

    Events are good.

    Interfaces are good.

    Concrete classes are good.

    Serialized references are good.

    What matters is:

    use the simplest dependency form
that matches the relationship.
