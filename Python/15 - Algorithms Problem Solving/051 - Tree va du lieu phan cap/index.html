    Bài 051 — Tree và dữ liệu phân cấp

    🎯 Hôm nay học gì?

    Nhiều dữ liệu không nằm trong một list phẳng.

    Chúng có cấu trúc phân cấp (hierarchical):

    • folder chứa folder/file con;
    • menu chứa submenu;
    • công ty có phòng ban và nhóm con;
    • game có skill tree;
    • giao diện có component chứa component con.

    Cấu trúc phù hợp để mô hình hóa loại dữ liệu này là tree — cây.

    Trong bài này, bạn sẽ học:

    • tree là gì;
    • node, root, parent, child, sibling và leaf;
    • subtree, depth, height, level và path;
    • các invariants làm một cấu trúc trở thành tree;
    • biểu diễn node có danh sách children;
    • recursive type annotation bằng forward reference;
    • duyệt depth-first bằng recursion;
    • phân biệt preorder và postorder;
    • duyệt depth-first bằng stack;
    • duyệt breadth-first bằng queue;
    • hiểu thứ tự push/enqueue ảnh hưởng traversal;
    • tìm node và đường từ root đến node;
    • tổng hợp dữ liệu theo postorder;
    • phân tích time và space complexity theo n, h, w;
    • xây Asset Tree Explorer hoàn chỉnh.

    Ranh giới kiến thức

    Bài này chỉ xử lý valid tree:

    • có đúng một root;
    • mỗi node khác root có đúng một parent;
    • không có cycle;
    • một node object không được dùng làm child ở nhiều nơi;
    • node ID unique theo contract của project.

    Chúng ta chưa học:

    • graph tổng quát;
    • cycle detection;
    • visited set trong traversal;
    • shortest path;
    • weighted edge;
    • binary search tree;
    • heap;
    • tree balancing.

    Graph, cycle và visited sẽ học ở Bài 052.

    🧒 Hiểu cực đơn giản

    Hãy nhìn một cây folder:

    game-assets
├── audio
│   ├── theme.ogg
│   └── click.wav
├── images
│   ├── hero.png
│   └── enemies
│       └── slime.png
└── readme.txt

    game-assets là điểm bắt đầu trên cùng.

    Nó chứa ba node con:

    • audio;
    • images;
    • readme.txt.

    images lại chứa enemies.

    enemies lại chứa slime.png.

    Mỗi phần nhỏ có cùng shape:

    một node
→ có thể có các children
→ mỗi child lại là một node

    Đó là lý do recursion rất tự nhiên với tree.

    🧠 1. Tree là gì?

    Tree — cây là cấu trúc dữ liệu phân cấp gồm các nodes nối theo quan hệ parent–child.

    Một tree hợp lệ trong bài này có:

    1. một root;
    2. mỗi node khác root có đúng một parent;
    3. không có đường nào đi qua children rồi quay lại node cũ;
    4. mọi node đều đi tới được từ root;
    5. thứ tự children có ý nghĩa nếu contract nói vậy.

    Tree khác list phẳng:

    list: item → item → item

tree: parent
      ├── child
      │   └── grandchild
      └── child

    🧠 2. Node — đơn vị của tree

    Node — nút là một phần tử trong tree.

    Một node thường có:

    • dữ liệu riêng;
    • identity như ID;
    • zero hoặc nhiều children.

    Ví dụ node folder:

    id: images
name: Images
kind: folder
children: hero.png, enemies

    Ví dụ node file:

    id: hero
name: hero.png
kind: file
children: không có

    🧠 3. Root, parent và child

    Root — nút gốc

    Node duy nhất không có parent.

    Trong cây folder trên:

    root = game-assets

    Parent — nút cha

    Node trực tiếp chứa node khác.

    images là parent của hero.png và enemies

    Child — nút con

    Node trực tiếp nằm dưới một parent.

    hero.png là child của images

    Quan hệ parent/child là trực tiếp.

    game-assets không phải parent trực tiếp của slime.png; nó là ancestor.

    🧠 4. Ancestor, descendant và sibling

    Ancestor — tổ tiên

    Node nằm phía trên theo chuỗi parent.

    Ancestors của slime.png:

    enemies
images
game-assets

    Descendant — hậu duệ

    Node nằm phía dưới qua một hoặc nhiều bước child.

    slime.png là descendant của images và game-assets.

    Sibling — node cùng cha

    audio, images và readme.txt là siblings vì cùng parent game-assets.

    🧠 5. Leaf và internal node

    Leaf node — nút lá

    Node không có children.

    theme.ogg
click.wav
hero.png
slime.png
readme.txt

    Một folder rỗng cũng là leaf về cấu trúc vì không có children.

    Do đó:

    leaf ≠ file

    Leaf nói về children, còn file/folder là business kind.

    Internal node — nút trong

    Node có ít nhất một child.

    game-assets
audio
images
enemies

    🧠 6. Subtree — cây con

    Một node cùng toàn bộ descendants của nó tạo thành subtree — cây con.

    Subtree tại images:

    images
├── hero.png
└── enemies
    └── slime.png

    Điểm quan trọng:

    Mỗi subtree lại có shape giống một tree.

    Đây chính là recursive structure:

    tree
= root node
+ nhiều subtrees của children

    🧠 7. Depth, level và height

    Depth — độ sâu của node

    Số bước parent–child từ root đến node.

    Quy ước trong bài:

    root depth = 0
child của root depth = 1

    slime.png có depth 3:

    game-assets → images → enemies → slime.png

    Level — tầng

    Trong bài này, level được dùng cùng số với depth:

    level 0 = root
level 1 = children của root

    Một số tài liệu đánh số level từ 1. Luôn đọc contract.

    Height — chiều cao

    Số bước dài nhất từ một node đi xuống một leaf.

    Tree example có root height 3.

    Leaf có height 0.

    🧠 8. Path trong tree

    Path — đường đi là chuỗi nodes nối liên tiếp theo quan hệ tree.

    Path từ root đến slime.png:

    game-assets / images / enemies / slime.png

    Trong valid tree, mỗi node có đúng một parent nên có đúng một path từ root đến node đó.

    Điều này sẽ khác graph tổng quát, nơi có thể có nhiều paths.

    🧩 9. Biểu diễn tree bằng dictionary lồng nhau

    Cách đơn giản:

    menu = {
    "label": "Main",
    "children": [
        {
            "label": "Play",
            "children": [],
        },
        {
            "label": "Settings",
            "children": [
                {
                    "label": "Audio",
                    "children": [],
                }
            ],
        },
    ],
}

    Ưu điểm:

    • gần JSON;
    • dễ tạo nhanh;
    • phù hợp dữ liệu đơn giản.

    Nhược điểm:

    • key typo chỉ lộ khi chạy;
    • validation dễ bị rải rác;
    • behavior không nằm cùng model.

    Project sẽ dùng dataclass để model rõ hơn.

    🧠 10. Recursive data model

    🧠 12. Tree construction policy

    Trong bài này, tree được build top-down:

    1. tạo root;
    2. tạo node mới;
    3. attach node mới vào đúng một parent;
    4. không attach lại cùng object;
    5. không attach ancestor làm child;
    6. kiểm tra unique business ID sau khi build.

    API add_child() chặn:

    • file nhận child;
    • node tự làm child của chính nó.

    Nó chưa phải validator cho arbitrary graph.

    Input contract vẫn yêu cầu caller không tạo deeper cycle hoặc shared child. Bài 052 sẽ dùng visited để xử lý cấu trúc tổng quát hơn.

    🧠 13. Traversal — duyệt tree

    Tree traversal — duyệt cây là ghé thăm mỗi node theo một order có chủ đích.

    Hai nhóm chính trong bài:

    Depth-first traversal
→ đi sâu vào một subtree trước

Breadth-first traversal
→ đi theo từng level từ gần root ra xa

    Traversal order là một phần của contract.

    Cùng tree nhưng order khác có thể phục vụ nhiệm vụ khác.

    🧠 14. Depth-first preorder

    Preorder xử lý node trước children:

    visit node
→ traverse child 1 subtree
→ traverse child 2 subtree
→ ...

    Với tree:

    A
├── B
│   ├── D
│   └── E
└── C
    └── F

    Preorder left-to-right:

    A, B, D, E, C, F

    Preorder phù hợp khi:

    • in tree từ parent xuống children;
    • tạo outline;
    • tìm match và muốn parent được kiểm tra trước descendants;
    • copy metadata parent trước content con.

    🧩 15. Preorder bằng recursion

    🧠 16. Preorder invariant

    Trước khi traverse child tiếp theo:

    result chứa node hiện tại và toàn bộ nodes của các child subtrees trước đó theo preorder.

    Sau khi mọi child hoàn tất:

    result chứa toàn bộ subtree tại node hiện tại theo preorder.

    Recursive contract:

    collect_preorder(node, result)
→ append đúng preorder của subtree node vào result

    🧠 18. Depth-first postorder

    Postorder xử lý children trước node:

    traverse child 1 subtree
→ traverse child 2 subtree
→ ...
→ visit node

    Với tree A–F:

    D, E, B, F, C, A

    Postorder phù hợp khi parent cần kết quả của children:

    • tính tổng size subtree;
    • tính height;
    • tổng hợp report từ dưới lên;
    • lập kế hoạch cleanup children trước container — chỉ khi action được phép và có safety boundary.

    🧩 19. Postorder bằng recursion

    🧠 20. Depth-first bằng stack

    Recursion dùng call stack của Python.

    Ta có thể dùng explicit stack:

    def depth_first_with_stack(root):
    result = []
    work_stack = [root]

    while len(work_stack) > 0:
        current = work_stack.pop()
        result.append(current.node_id)

        for index in range(len(current.children) - 1, -1, -1):
            work_stack.append(current.children[index])

    return result

    Children được push từ phải sang trái để child bên trái nằm trên đỉnh và được pop trước.

    🔍 21. Vì sao phải push ngược?

    Node A có children:

    [B, C]

    Muốn visit B trước C.

    Stack LIFO nên phải push:

    push C
push B

top → B
       C

    Nếu push B rồi C, C sẽ được pop trước và traversal trở thành right-to-left.

    🧠 22. Recursive DFS hay stack DFS?

    Chọn recursive DFS khi:

    • tree depth an toàn;
    • recursive shape làm code rõ;
    • cần postorder aggregation tự nhiên;
    • muốn parent frame chờ child result.

    Chọn explicit stack khi:

    • tree có thể sâu;
    • muốn tránh Python recursion depth limit;
    • muốn pause/resume hoặc inspect worklist;
    • muốn kiểm soát traversal state trực tiếp.

    Cả hai có thể tạo cùng preorder nếu push order đúng.

    🧠 23. Breadth-first traversal

    Breadth-first traversal — duyệt theo chiều rộng xử lý level gần root trước.

    Với tree A–F:

    A, B, C, D, E, F

    Order theo level:

    level 0: A
level 1: B, C
level 2: D, E, F

    Queue FIFO phù hợp vì nodes được phát hiện trước cần được xử lý trước.

    🧩 24. Breadth-first bằng queue

    from collections import deque


def breadth_first(root):
    result = []
    work_queue = deque([root])

    while len(work_queue) > 0:
        current = work_queue.popleft()
        result.append(current.node_id)

        for child in current.children:
            work_queue.append(child)

    return result

    Children được enqueue left-to-right.

    FIFO giữ order đó trong cùng level.

    🧩 25. BFS kèm depth

    Queue có thể giữ tuple (node, depth):

    from collections import deque


def breadth_first_with_depth(root):
    result = []
    work_queue = deque([(root, 0)])

    while len(work_queue) > 0:
        current, depth = work_queue.popleft()
        result.append((current.node_id, depth))

        for child in current.children:
            work_queue.append((child, depth + 1))

    return result

    Mỗi queued item mang đủ state để xử lý khi đến lượt.

    🧠 33. Complexity của tree traversal

    Gọi:

    • n: tổng số nodes;
    • h: tree height;
    • w: maximum width — số nodes lớn nhất trong một level.

    Nếu valid tree và mỗi node được visit một lần:

    DFS time: O(n)
BFS time: O(n)

    Recursive DFS:

    call-stack space: O(h)

    Explicit stack DFS:

    work-stack space: O(n) worst case

    BFS:

    queue space: O(w), worst case O(n)

    Output list chứa mọi IDs dùng thêm O(n) space. Nếu chỉ print/process từng node, output collection có thể không cần.

    🧠 34. Shape quyết định memory

    Tree rất sâu

    A
└── B
    └── C
        └── D
    • recursive DFS depth lớn;
    • BFS queue nhỏ.

    Tree rất rộng

          A
 ├─ B ├─ C ├─ D ├─ E ...
    • recursion depth nhỏ;
    • BFS queue có thể lớn.

    Không chỉ n; shape của tree ảnh hưởng memory behavior.

    🧠 35. Valid tree assumption quan trọng

    Các traversal trong bài không có visited set.

    Chúng đúng khi input là valid tree.

    Nếu một child trỏ ngược tới ancestor:

    A → B → A → B → ...

    Recursive traversal có thể gặp RecursionError; iterative traversal có thể không dừng.

    Đừng thêm step limit rồi gọi structure đó là tree hợp lệ.

    Root cause là input không thỏa tree contract.

    Bài 052 sẽ mở rộng sang graph và dùng visited để tránh revisit/cycle.

def collect_preorder(node, result):
    result.append(node.node_id)

    for child in node.children:
        collect_preorder(child, result)


def depth_first_recursive(root):
    result = []
    collect_preorder(root, result)
    return result


def depth_first_with_stack(root):
    result = []
    work_stack = [root]

    while len(work_stack) > 0:
        current = work_stack.pop()
        result.append(current.node_id)

        for index in range(len(current.children) - 1, -1, -1):
            work_stack.append(current.children[index])

    return result


def breadth_first_with_depth(root):
    result = []
    work_queue = deque([(root, 0)])

    while len(work_queue) > 0:
        current, depth = work_queue.popleft()
        result.append((current.node_id, depth))

        for child in current.children:
            work_queue.append((child, depth + 1))

    return result


def validate_unique_ids(root):

def summarize_subtree(node, depth=0):
    if node.kind == "file":
        return TreeSummary(
            folders=0,
            files=1,
            total_size_bytes=node.size_bytes,
            max_depth=depth,
        )

    summary = TreeSummary(
        folders=1,
        files=0,
        total_size_bytes=0,
        max_depth=depth,
    )

    for child in node.children:
        child_summary = summarize_subtree(child, depth + 1)
        summary.folders += child_summary.folders
        summary.files += child_summary.files
        summary.total_size_bytes += child_summary.total_size_bytes

        if child_summary.max_depth > summary.max_depth:
            summary.max_depth = child_summary.max_depth

    return summary


def snapshot_tree(root):
    snapshot = []
    work_queue = deque([(root, 0)])

    while len(work_queue) > 0:
        current, depth = work_queue.popleft()
        child_ids = []

        for child in current.children:
            child_ids.append(child.node_id)
            work_queue.append((child, depth + 1))

        snapshot.append(
            (
                current.node_id,
                current.name,
                current.kind,
                current.size_bytes,
                depth,
                tuple(child_ids),
            )
        )

    return snapshot

    📌 71. Thuật ngữ quan trọng

    Hierarchical data — dữ liệu phân cấp

    Dữ liệu có quan hệ nhiều tầng parent–child.

    Tree — cây

    Cấu trúc phân cấp có một root, mỗi non-root node có một parent và không cycle.

    Node — nút

    Một phần tử mang data và có thể có children trong tree.

    Root — nút gốc

    Node duy nhất không có parent.

    Parent — nút cha

    Node trực tiếp chứa child.

    Child — nút con

    Node trực tiếp nằm dưới parent.

    Ancestor — tổ tiên

    Node nằm phía trên qua một hoặc nhiều parent steps.

    Descendant — hậu duệ

    Node nằm phía dưới qua một hoặc nhiều child steps.

    Sibling — node cùng cha

    Các nodes có cùng direct parent.

    Leaf — nút lá

    Node không có children.

    Internal node — nút trong

    Node có ít nhất một child.

    Subtree — cây con

    Một node cùng toàn bộ descendants của nó.

    Depth — độ sâu

    Số parent–child steps từ root đến node.

    Height — chiều cao

    Số steps dài nhất từ node đi xuống một leaf.

    Width — độ rộng

    Số nodes trong một level; maximum width là level rộng nhất.

    Path — đường đi

    Chuỗi nodes nối liên tiếp theo relationship của structure.

    Forward reference — tham chiếu kiểu về phía trước

    Type annotation tham chiếu tới class chưa hoàn tất definition, trong bài được viết bằng string.

    Tree traversal — duyệt cây

    Quá trình ghé thăm tree nodes theo order có chủ đích.

    Depth-first traversal — duyệt theo chiều sâu

    Đi sâu vào một child subtree trước khi chuyển sang sibling tiếp theo.

    Breadth-first traversal — duyệt theo chiều rộng

    Xử lý nodes theo từng level từ gần root ra xa.

    Preorder

    Traversal xử lý parent node trước child subtrees.

    Postorder

    Traversal xử lý child subtrees trước parent node.

    Structural base case — trường hợp cơ sở theo cấu trúc

    Điểm recursion tự dừng do node không còn children để gọi tiếp.

    Maximum width — độ rộng tối đa

    Số nodes lớn nhất xuất hiện trong cùng một level.

    ✅ 72. Điều cần nhớ

    1. Tree mô hình dữ liệu phân cấp bằng parent–child relationships.
    2. Valid tree có một root, mỗi non-root node một parent và không cycle/shared child.
    3. Leaf là node không children; leaf không đồng nghĩa file.
    4. Mỗi node cùng descendants tạo một subtree cùng shape với tree.

    6. Recursive node model cần children list riêng cho mỗi instance.
    7. Preorder xử lý node trước children; postorder xử lý children trước node.
    8. Empty children có thể là structural base case.
    9. Recursive DFS dùng call stack; iterative DFS dùng explicit stack.
    10. Muốn stack DFS giữ left-to-right order, push children right-to-left.
    11. BFS dùng queue để xử lý level gần root trước.
    12. Recursive result phải được return xuyên qua parent frames.
    13. Temporary path phải pop node của branch thất bại.
    14. Postorder phù hợp khi parent tổng hợp child results.
    15. DFS/BFS visit mỗi node một lần nên time O(n) trên valid tree.
    16. Recursive DFS memory phụ thuộc height h; BFS queue phụ thuộc width w.
    17. Tree shape ảnh hưởng memory dù tổng node count bằng nhau.
    18. Snapshot phải giữ fields và ordered child IDs để kiểm tra source invariant.
    19. Traversal trong bài giả định valid finite tree và chưa dùng visited.
    20. Graph/cycle/visited sẽ được học riêng ở Bài 052.
