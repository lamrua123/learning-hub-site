    Bài 061 — Form, validation và persistence trong GUI

    🎯 Hôm nay học gì?

    Sau bài này, bạn có thể:

    • hiểu form GUI có state và lifecycle riêng, không chỉ là vài ô Entry;
    • thiết kế hai chế độ create và edit rõ ràng;
    • dùng ttk.Combobox, ttk.Checkbutton, tk.BooleanVar và ttk.Treeview;
    • liên kết row được chọn với business ID ổn định;
    • phân biệt validation ở UI, service và persistence boundary;
    • normalize dữ liệu trước khi validate và kiểm tra duplicate;
    • đưa focus tới field lỗi và hiển thị feedback mà không làm app crash;
    • xác nhận thao tác xóa bằng messagebox;
    • bắt DataError bên trong event handler;
    • refresh table từ service state thay vì coi widget là nguồn sự thật;
    • lưu JSON theo luồng candidate → temporary file → replace → commit;
    • xây Contact Manager hoàn chỉnh theo kiến trúc Bài 059 và GUI Bài 060.

    🧒 Hiểu cực đơn giản

    Một form quản lý contact giống quầy tiếp nhận hồ sơ:

    người dùng điền form
→ UI kiểm tra input cơ bản
→ service kiểm tra quy tắc contact
→ repository lưu dữ liệu
→ bảng được render lại từ state đã lưu

    Nếu người dùng chọn một contact trong bảng:

    row được chọn
→ lấy contact ID
→ hỏi service contact tương ứng
→ điền form
→ chuyển sang edit mode

    Form không tự sửa JSON. Bảng không trở thành “database thứ hai”.

    🧠 1. Form có state riêng

    Form không chỉ chứa text. Nó còn có trạng thái:

    • đang tạo contact mới hay sửa contact cũ;
    • contact ID nào đang được chọn;
    • field nào đang có lỗi;
    • button Delete có được bật không;
    • message hiện tại là success hay failure.

    Trong project:

    self._selected_id = None

    Ý nghĩa:

    selected_id is None → create mode
selected_id là int  → edit mode cho contact đó

    Đây là form state, thuộc UI. Business contact state vẫn do service sở hữu.

    🧠 2. Lifecycle của form

    Vòng đời form (form lifecycle):

    CREATE MODE
  → user nhập fields
  → Save
  → add thành công
  → chọn row mới
  → EDIT MODE
  → sửa fields hoặc Delete
  → New/Clear
  → CREATE MODE

    Mỗi transition cần cập nhật đồng bộ:

    • _selected_id;
    • field variables;
    • label mode;
    • text của Save button;
    • trạng thái Delete button;
    • selection trong table.

    Nếu chỉ đổi một phần, UI có thể hiện “Edit mode” nhưng lại chạy add.

    🧠 3. Validation nhiều lớp

    UI validation

    UI hiểu widget và trải nghiệm người dùng:

    • field Name đang rỗng;
    • đưa focus về Name Entry;
    • text từ Entry chưa thể đọc;
    • hiện message ngay cạnh form.

    Business validation

    Service bảo vệ rules bất kể caller là GUI, CLI hay code khác:

    • name tối đa 80 ký tự;
    • phone có 7–15 chữ số sau normalize;
    • category phải thuộc tập cho phép;
    • phone không được trùng;
    • contact ID phải tồn tại.

    Persistence validation

    Repository/model bảo vệ dữ liệu đọc từ file:

    • JSON root và version đúng;
    • records là list;
    • fields/types hợp lệ;
    • IDs không trùng;
    • phones không trùng.

    Một invariant quan trọng có thể được kiểm tra ở nhiều boundary vì mỗi boundary bảo vệ một nguồn input khác nhau.

    🧠 4. Validation không chỉ nằm trong GUI

    Sai:

    def on_save(self):
    if self.phone_var.get().isdigit():
        self.service.add_contact(...)

    Rồi service tin mọi caller.

    Một script khác vẫn có thể gọi:

    🧠 5. Normalize trước khi so sánh

    Người dùng có thể nhập cùng số điện thoại theo nhiều cách:

    090 123 4567

    Project cho phép chữ số, space, -, ( và ), rồi normalize thành:

    0901234567

    Normalization không có nghĩa “xóa mọi ký tự lạ”. Ký tự A vẫn bị từ chối rõ ràng.

    🧩 16. models.py

    from dataclasses import dataclass, field


CATEGORIES = ("personal", "work", "other")
DIGITS = "0123456789"


@dataclass
class Contact:
    id: int
    name: str
    phone: str
    category: str
    favorite: bool = False

    def copy(self):
        return Contact(
            self.id,
            self.name,
            self.phone,
            self.category,
            self.favorite,
        )

    def to_dict(self):
        return {
            "id": self.id,
            "name": self.name,
            "phone": self.phone,
            "category": self.category,
            "favorite": self.favorite,
        }

    @classmethod
    def from_dict(cls, data):
        if not isinstance(data, dict):
            raise ValueError("Mỗi contact phải là dictionary")

        required_keys = {"id", "name", "phone", "category", "favorite"}

        if set(data.keys()) != required_keys:
            raise ValueError("Contact fields không đúng schema")

        contact_id = data["id"]
        name = data["name"]
        phone = data["phone"]
        category = data["category"]
        favorite = data["favorite"]

        if type(contact_id) is not int or contact_id <= 0:
            raise ValueError("Contact ID phải là số nguyên dương")

        if not isinstance(name, str) or name.strip() == "":
            raise ValueError("Contact name phải là chuỗi không rỗng")

        clean_name = name.strip()

        if len(clean_name) > 80:
            raise ValueError("Contact name tối đa 80 ký tự")

        if not isinstance(phone, str) or phone == "":
            raise ValueError("Contact phone phải là chuỗi không rỗng")

        for character in phone:
            if character not in DIGITS:
                raise ValueError("Contact phone phải chứa digits đã normalize")

        if not 7 <= len(phone) <= 15:
            raise ValueError("Contact phone phải có 7 đến 15 chữ số")

        if category not in CATEGORIES:
            raise ValueError("Contact category không hợp lệ")

        if type(favorite) is not bool:
            raise ValueError("Contact favorite phải là Boolean")

        return cls(contact_id, clean_name, phone, category, favorite)


@dataclass
class OperationResult:
    success: bool
    code: str
    message: str
    contacts: list = field(default_factory=list)


def success(message, contacts=None):
    if contacts is None:
        contacts = []

    return OperationResult(True, "ok", message, contacts)


def failure(code, message):
    return OperationResult(False, code, message)

    Contact.from_dict() bảo vệ persistence boundary. Service tạo contacts theo cùng invariants.

    🧩 18. repository.py

    import json
from pathlib import Path

from errors import DataError
from models import Contact


DATA_VERSION = 1


class JsonContactRepository:
    def __init__(self, path):
        self._path = Path(path)

    def load(self):
        if not self._path.exists():
            return []

        try:
            text = self._path.read_text(encoding="utf-8")
            data = json.loads(text)
            return self._decode(data)
        except (OSError, json.JSONDecodeError, TypeError, ValueError) as error:
            raise DataError("Không thể load contacts: " + str(error)) from error

    def save(self, contacts):
        temp_path = self._path.with_suffix(self._path.suffix + ".tmp")

        try:
            data = {
                "version": DATA_VERSION,
                "contacts": [contact.to_dict() for contact in contacts],
            }
            self._decode(data)
            text = json.dumps(data, ensure_ascii=False, indent=2)
            self._path.parent.mkdir(parents=True, exist_ok=True)
            temp_path.write_text(text, encoding="utf-8")
            json.loads(temp_path.read_text(encoding="utf-8"))
            temp_path.replace(self._path)
        except (OSError, json.JSONDecodeError, TypeError, ValueError) as error:
            raise DataError("Không thể save contacts: " + str(error)) from error

    def _decode(self, data):
        if not isinstance(data, dict):
            raise ValueError("Data root phải là dictionary")

        if set(data.keys()) != {"version", "contacts"}:
            raise ValueError("Data root fields không đúng schema")

        if type(data["version"]) is not int or data["version"] != DATA_VERSION:
            raise ValueError("Data version không được hỗ trợ")

        raw_contacts = data["contacts"]

        if not isinstance(raw_contacts, list):
            raise ValueError("contacts phải là list")

        contacts = []
        used_ids = set()
        used_phones = set()

        for raw_contact in raw_contacts:
            contact = Contact.from_dict(raw_contact)

            if contact.id in used_ids:
                raise ValueError("Contact ID bị trùng: " + str(contact.id))

            if contact.phone in used_phones:
                raise ValueError("Contact phone bị trùng: " + contact.phone)

            used_ids.add(contact.id)
            used_phones.add(contact.phone)
            contacts.append(contact)

        return contacts

class ContactService:
    def __init__(self, repository):
        self._repository = repository
        self._contacts = []
        self._started = False

    def start(self):
        contacts = self._repository.load()
        self._contacts = self._copy_list(contacts)
        self._started = True

    def list_contacts(self):
        self._require_started()
        contacts = self._copy_list(self._contacts)
        contacts.sort(key=lambda contact: (contact.name.lower(), contact.id))
        return success("Có " + str(len(contacts)) + " contact", contacts)

    def get_contact(self, contact_id):
        self._require_started()

        if type(contact_id) is not int or contact_id <= 0:
            return failure("invalid_id", "Contact ID phải là số nguyên dương")

        contact = self._find(self._contacts, contact_id)

        if contact is None:
            return failure("not_found", "Không tìm thấy contact")

        return success("Đã tìm thấy contact", [contact.copy()])

    def add_contact(self, name, phone, category, favorite):
        self._require_started()
        validation, clean_name, clean_phone = self._validate_fields(
            name,
            phone,
            category,
            favorite,
        )

        if not validation.success:
            return validation

        if self._phone_exists(clean_phone):
            return failure("duplicate_phone", "Phone đã tồn tại")

        contact = Contact(
            self._next_id(),
            clean_name,
            clean_phone,
            category,
            favorite,
        )
        candidate = self._copy_list(self._contacts)
        candidate.append(contact)
        self._commit(candidate)
        return success("Đã thêm contact " + str(contact.id), [contact.copy()])

    def update_contact(self, contact_id, name, phone, category, favorite):
        self._require_started()

        if type(contact_id) is not int or contact_id <= 0:
            return failure("invalid_id", "Contact ID phải là số nguyên dương")

        validation, clean_name, clean_phone = self._validate_fields(
            name,
            phone,
            category,
            favorite,
        )

        if not validation.success:
            return validation

        candidate = self._copy_list(self._contacts)
        contact = self._find(candidate, contact_id)

        if contact is None:
            return failure("not_found", "Không tìm thấy contact")

        if self._phone_exists(clean_phone, ignored_id=contact_id):
            return failure("duplicate_phone", "Phone đã tồn tại")

        contact.name = clean_name
        contact.phone = clean_phone
        contact.category = category
        contact.favorite = favorite
        self._commit(candidate)
        return success("Đã cập nhật contact " + str(contact.id), [contact.copy()])

    def remove_contact(self, contact_id, confirmed):
        self._require_started()

        if type(contact_id) is not int or contact_id <= 0:
            return failure("invalid_id", "Contact ID phải là số nguyên dương")

        if type(confirmed) is not bool or not confirmed:
            return failure("confirmation_required", "Cần xác nhận trước khi xóa")

        candidate = self._copy_list(self._contacts)
        contact = self._find(candidate, contact_id)

        if contact is None:
            return failure("not_found", "Không tìm thấy contact")

        candidate.remove(contact)
        self._commit(candidate)
        return success("Đã xóa contact " + str(contact_id))

    def _validate_fields(self, name, phone, category, favorite):
        if not isinstance(name, str):
            return failure("invalid_name", "Name phải là chuỗi"), None, None

        clean_name = name.strip()

        if clean_name == "":
            return failure("empty_name", "Name không được rỗng"), None, None

        if len(clean_name) > 80:
            return failure("name_too_long", "Name tối đa 80 ký tự"), None, None

        phone_result, clean_phone = self._normalize_phone(phone)

        if not phone_result.success:
            return phone_result, None, None

        if category not in CATEGORIES:
            return failure("invalid_category", "Category không hợp lệ"), None, None

        if type(favorite) is not bool:
            return failure("invalid_favorite", "Favorite phải là Boolean"), None, None

        return success("Fields hợp lệ"), clean_name, clean_phone

    def _normalize_phone(self, phone):
        if not isinstance(phone, str):
            return failure("invalid_phone", "Phone phải là chuỗi"), None

        clean_phone = ""
        allowed_separators = " -()"

        for character in phone.strip():
            if character in DIGITS:
                clean_phone = clean_phone + character
            elif character not in allowed_separators:
                return (
                    failure(
                        "invalid_phone_character",
                        "Phone chỉ được chứa chữ số, space, -, (, )",
                    ),
                    None,
                )

        if not 7 <= len(clean_phone) <= 15:
            return (
                failure("invalid_phone_length", "Phone phải có 7 đến 15 chữ số"),
                None,
            )

        return success("Phone hợp lệ"), clean_phone

    def _phone_exists(self, phone, ignored_id=None):
        for contact in self._contacts:
            if contact.id != ignored_id and contact.phone == phone:
                return True

        return False

    def _next_id(self):
        largest = 0

        for contact in self._contacts:
            if contact.id > largest:
                largest = contact.id

        return largest + 1

    def _find(self, contacts, contact_id):
        for contact in contacts:
            if contact.id == contact_id:
                return contact

        return None

    def _copy_list(self, contacts):
        copies = []

        for contact in contacts:
            copies.append(contact.copy())

        return copies

    def _commit(self, candidate):
        self._repository.save(candidate)
        self._contacts = candidate

    def _require_started(self):
        if not self._started:
            raise RuntimeError("ContactService chưa được start")

    Thử 1 — Thêm category

    CATEGORIES = ("personal", "work", "other", "family")

    Quan sát Combobox và kiểm tra model/service cùng dùng một constant.

    Thử 2 — Favorite lên đầu

    contacts.sort(
    key=lambda contact: (
        not contact.favorite,
        contact.name.lower(),
        contact.id,
    )
)

    Giải thích vì sao not favorite đưa favorite lên trước.

    Thử 3 — Bỏ reselect

    Tạm bỏ selected_id=saved_id khi refresh. Quan sát form và selection sau save.

    Thử 4 — Failure injection

    Tạo repository có save() luôn phát DataError. Xác nhận GUI hiện dialog, table không có row mới và service state không đổi.

    Thử 5 — Parent dialog

    Bỏ parent=self._root, quan sát dialog trên hệ điều hành rồi đặt lại parent rõ ràng.

    🐛 38. Bug Lab

    Theo quy trình:

    Quan sát → xác định UI/logic/data boundary → đoán nguyên nhân → sửa → kiểm tra lại.

    Bug 1 — Row index được dùng làm ID

    Sau khi xóa contact đầu tiên, edit row đầu sửa nhầm record.

    Gợi ý: dùng iid=str(contact.id) và đọc ID từ selection.

    Bug 2 — Form vẫn ở create mode

    Selection handler điền fields nhưng quên cập nhật _selected_id. Gom transition vào _set_edit_mode().

    Bug 3 — New chỉ xóa fields

    _selected_id, Delete button và table selection vẫn giữ state cũ. Những phần nào phải reset?

    Bug 4 — Duplicate raw phone

    090-123-4567 và 0901234567 bị xem là khác. Normalize trước duplicate check.

    Bug 5 — Update giữ phone bị báo trùng

    Duplicate scan không có ignored_id. Bỏ qua chính record đang update, không bỏ qua record khác.

    Bug 6 — Widget là database

    UI đọc Treeview rows rồi save JSON trực tiếp. Treeview thiếu invariant/model fields nào? Layer nào phải sở hữu state?

    Bug 7 — Commit trước save

    self._contacts = candidate
self._repository.save(candidate)

    Đảo lại theo candidate → save → commit.

    Bug 8 — Callback che mọi lỗi

    except Exception:
    pass

    Chỉ bắt expected DataError; không che programming error.

    Bug 9 — Quên .get() của BooleanVar

    Service nhận Tkinter variable object thay vì Boolean. Boundary phải truyền value nào?

    Bug 10 — Table không co giãn

    Treeview có sticky="nsew" nhưng window kéo rộng không đổi. Kiểm tra rowconfigure/columnconfigure(weight=1) ở root và table_area.

    📌 43. Thuật ngữ quan trọng

    • trạng thái form (form state): fields, mode và selected ID tạm thời của form.
    • vòng đời form (form lifecycle): chuỗi transitions create/edit/save/reset.
    • create mode: chế độ tạo record mới.
    • edit mode: chế độ sửa record đã tồn tại.
    • chuẩn hóa (normalization): đưa nhiều biểu diễn về một dạng chuẩn trước so sánh.
    • validation nhiều lớp (layered validation): kiểm tra phù hợp ở UI, business và persistence boundaries.
    • bảng dữ liệu (data table): widget hiển thị records theo hàng/cột.
    • Treeview: widget ttk hiển thị tree hoặc table.
    • item identifier (iid): ID nội bộ ổn định của Treeview item.
    • sự kiện ảo (virtual event): event cấp widget như <<TreeviewSelect>>.
    • readonly Combobox: hộp chọn chỉ nhận values định sẵn.
    • hộp thoại xác nhận (confirmation dialog): dialog yêu cầu user xác nhận action.
    • view projection: dữ liệu hiển thị được tạo từ source state.
    • dirty state: form đã khác dữ liệu lần cuối load/save.
    • refresh: dựng lại view từ state hiện tại.
    • CRUD: nhóm operations Create, Read, Update, Delete.

    ✅ Điều cần nhớ

    1. Form là state machine nhỏ với create/edit lifecycle.
    2. _selected_id giữ business ID, không giữ row index.
    3. UI validation giúp feedback; service giữ invariant; repository bảo vệ file.
    4. Normalize trước length/duplicate check và persistence.
    5. Readonly widgets giảm input sai nhưng không thay business validation.
    6. Treeview là view; service vẫn là nguồn sự thật.
    7. Chọn row lấy contact snapshot từ service bằng ID.
    8. Chỉ refresh UI sau khi save và commit thành công.
    9. Update duplicate check bỏ qua chính record đang sửa.
    10. Delete cần confirmation UI và confirmed service contract.
    11. DataError trong callback phải được báo rõ.
    12. Candidate → temporary save/replace → commit giữ persistence và memory state nhất quán hơn.
