    Bài 065 — Batch automation có retry, quarantine và resume

    🎯 Hôm nay học gì?

    Ta sẽ xây JSON Batch Normalizer, một automation xử lý nhiều file độc lập:

    workspace/inbox/*.json
→ đọc + validate
→ ghi JSON đã format vào workspace/output/

    Project có các khả năng quan trọng:

    • một item lỗi không làm mất kết quả của item khác;
    • phân biệt lỗi tạm thời và lỗi vĩnh viễn;
    • retry có giới hạn và delay tăng dần;
    • item không thể xử lý được đưa vào quarantine logic;
    • manifest được checkpoint trước/sau mỗi attempt;
    • process dừng giữa chừng có thể resume;
    • output write là atomic và idempotent;
    • source files luôn read-only;
    • có report và audit log.

    Đây là bước chuyển từ “chạy một loop” sang thiết kế một batch workflow có trạng thái.

    🧒 Hiểu cực đơn giản

    Hãy tưởng tượng một bưu điện xử lý 100 kiện hàng.

    Một kiện thiếu địa chỉ không nên khiến 99 kiện hợp lệ bị giữ lại.

    Nhân viên cần chia kiện thành các trạng thái:

    pending       đang chờ
processing    đang xử lý
succeeded     đã xong
retryable     gặp trục trặc có thể thử lại
quarantined   được tách riêng để điều tra

    Nếu mất điện ở kiện số 43, ca làm sau mở sổ manifest:

    1–42 succeeded → bỏ qua
43 processing  → đối chiếu rồi thử lại an toàn
44–100 pending → tiếp tục

    Đó là resume: tiếp tục từ trạng thái đã lưu, không làm lại mù quáng từ đầu.

    🧠 1. Contract của JSON Batch Normalizer

    Workspace

    workspace/
├── inbox/       source JSON, chỉ đọc
├── output/      normalized JSON
├── quarantine/  error record cho item bị cô lập
└── .batch_state/
    ├── manifest.json
    ├── report.json
    └── batch.log

    Input hợp lệ

    • file trực tiếp trong inbox;
    • extension .json, không phân biệt hoa thường;
    • không phải symbolic link;
    • JSON root phải là dictionary.

    Output

    • giữ nguyên dữ liệu;
    • keys được sắp xếp;
    • indent 2 spaces;
    • UTF-8;
    • không overwrite output khác nội dung.

    Batch policy

    • FileNotFoundError, JSON hỏng, root sai kiểu, source bị thay đổi → permanent failure;
    • PermissionError và I/O OSError khác → retryable failure;
    • retry tối đa max_attempts cho mỗi item;
    • hết attempt → quarantine;
    • quarantine của một item không dừng các item còn lại;
    • manifest/log/quarantine store hỏng → dừng toàn batch vì không còn khả năng theo dõi an toàn.

    🧠 2. Item failure khác infrastructure failure

    Item failure

    Chỉ liên quan một file:

    bad.json sai cú pháp
locked.json tạm thời không đọc được
one.json bị sửa sau khi lập plan

    Policy: retry hoặc quarantine item đó rồi tiếp tục batch.

    Infrastructure failure

    Hệ thống theo dõi chung không hoạt động:

    không save được manifest
không ghi được quarantine record
không mở được audit log

    Policy: dừng batch. Nếu cứ chạy, tool có thể thay đổi output nhưng mất bằng chứng về tiến độ.

    Phân biệt hai cấp failure giúp ta không “catch mọi thứ rồi continue”.

    🧠 3. Retry chỉ dành cho lỗi có khả năng tạm thời

    Retry phù hợp khi lần thử sau có cơ hội thành công mà input không cần sửa:

    file đang bị ứng dụng khác khóa
ổ đĩa/network share gián đoạn ngắn
temporary I/O error

    Retry không giúp JSON thiếu dấu } tự sửa.

    invalid JSON
→ retry 1: vẫn invalid
→ retry 2: vẫn invalid
→ retry 100: vẫn invalid

    Lỗi vĩnh viễn phải đi thẳng tới quarantine.

    🧠 4. Retry budget thuộc về từng item

    Sai:

    batch có 3 retries tổng cộng

    Một item lỗi có thể dùng hết budget của mọi item khác.

    Đúng:

    item A: attempts 1/3
item B: attempts 1/3
item C: attempts 2/3

    attempts được lưu trong từng BatchItem.

    Ta dùng exponential backoff đơn giản:

    calculated_delay = base_delay × 2^(attempts - 1)
delay = min(calculated_delay, 300 giây)

    Với base delay 1 giây:

    sau attempt 1 → chờ 1 giây
sau attempt 2 → chờ 2 giây
sau attempt 3 → hết budget, không chờ nữa

    Project local này chưa cần jitter. Khi nhiều client gọi một service qua mạng, jitter giúp tránh tất cả retry cùng lúc.

    🧠 5. Quarantine là state và artifact

    Project không move source hỏng. Source vẫn ở inbox để bảo toàn bằng chứng.

    Quarantine gồm:

    1. item status là quarantined trong manifest;
    2. một error record JSON trong folder quarantine.

    Ví dụ:

    {
  "source": "C:/work/inbox/bad.json",
  "attempts": 1,
  "reason": "JSON không hợp lệ: ..."
}

    Vì manifest đã ghi status, resume sẽ bỏ qua item này. Operator có thể sửa source rồi tạo batch mới hoặc dùng một recovery workflow riêng.

    Không tự đưa item quarantined về pending chỉ vì process chạy lại.

    🧠 6. Status machine của một item

    pending
→ processing
→ succeeded

pending
→ processing
→ retryable_failed
→ processing
→ succeeded

pending
→ processing
→ quarantine_pending
→ quarantined

    Khi crash:

    processing
→ resume chuyển về pending
→ chạy lại bằng operation idempotent

    quarantine_pending cũng có ý nghĩa:

    manifest đã ghi ý định quarantine
→ chưa chắc error record đã ghi xong

    Resume có thể ghi lại error record an toàn rồi chuyển sang quarantined.

    🧠 8. Vì sao lưu processing trước khi xử lý?

    Nếu chỉ save sau success:

    manifest: pending
→ process bắt đầu
→ output được ghi
→ crash trước khi save succeeded

    Manifest không cho biết item đã bắt đầu.

    Workflow tốt hơn:

    attempts += 1
status = processing
save manifest
→ process
→ status = succeeded
save manifest

    Nếu crash, resume nhìn thấy processing và biết cần reconciliation.

    🧩 11. planner.py — build batch plan

    def build_plan(workspace, max_attempts, base_delay_seconds):
    validate_settings(max_attempts, base_delay_seconds)
    paths = make_paths(workspace)
    root = paths["workspace"]
    inbox = paths["inbox"]
    output = paths["output"]
    quarantine = paths["quarantine"]

    try:
        if not root.exists() or not root.is_dir():
            raise BatchError("Workspace không tồn tại hoặc không phải folder")

        if inbox.is_symlink() or not inbox.exists() or not inbox.is_dir():
            raise BatchError("inbox phải là folder thật, không phải symbolic link")

        entries = list(inbox.iterdir())
    except OSError as error:
        raise BatchError("Không thể scan inbox: " + str(error)) from error

    plan = BatchPlan(
        workspace=str(root),
        max_attempts=max_attempts,
        base_delay_seconds=float(base_delay_seconds),
    )

    for managed_path in [output, quarantine, paths["state"]]:
        try:
            if managed_path.is_symlink():
                plan.problems.append(
                    str(managed_path) + " không được là symbolic link"
                )
            elif managed_path.exists() and not managed_path.is_dir():
                plan.problems.append(str(managed_path) + " phải là folder")
        except OSError as error:
            plan.problems.append(str(managed_path) + ": " + str(error))

    manifest_path = paths["state"] / "manifest.json"

    try:
        if manifest_path.exists() or manifest_path.is_symlink():
            plan.problems.append(
                "Manifest đã tồn tại; hãy resume hoặc archive batch cũ"
            )
    except OSError as error:
        plan.problems.append(str(manifest_path) + ": " + str(error))

    entries.sort(key=lambda path: path.name.casefold())
    reserved_outputs = set()
    reserved_quarantine = set()

    for source in entries:
        try:
            if source.is_symlink() or not source.is_file():
                continue

            if source.suffix.lower() != ".json":
                continue

            stat_result = source.stat()
        except OSError as error:
            plan.problems.append(str(source) + ": " + str(error))
            continue

        destination = output / source.name
        quarantine_record = quarantine / (source.name + ".error.json")
        output_key = str(destination).casefold()
        quarantine_key = str(quarantine_record).casefold()

        if output_key in reserved_outputs:
            plan.problems.append(
                source.name + ": destination trùng trong batch"
            )
            continue

        if quarantine_key in reserved_quarantine:
            plan.problems.append(
                source.name + ": quarantine record trùng trong batch"
            )
            continue

        try:
            if destination.exists() or destination.is_symlink():
                plan.problems.append(
                    source.name + ": output đã tồn tại; không tạo batch mới"
                )
                continue

            if quarantine_record.exists() or quarantine_record.is_symlink():
                plan.problems.append(
                    source.name + ": quarantine record đã tồn tại"
                )
                continue
        except OSError as error:
            plan.problems.append(str(destination) + ": " + str(error))
            continue

        reserved_outputs.add(output_key)
        reserved_quarantine.add(quarantine_key)
        plan.items.append(
            BatchItem(
                source=str(source),
                destination=str(destination),
                quarantine_record=str(quarantine_record),
                source_size=stat_result.st_size,
                source_modified_ns=stat_result.st_mtime_ns,
            )
        )

    return plan

    Một plan là snapshot. File JSON xuất hiện sau discovery không tự chen vào batch đang resume. Nó thuộc batch mới sau này.

    🧠 17. Output operation phải idempotent

    Crash window:

    output đã ghi thành công
→ chưa save succeeded
→ process dừng

    Resume sẽ thử item đó lại.

    Policy của processor:

    output chưa tồn tại → ghi atomic
output tồn tại và bằng normalized source → coi là already_current
output tồn tại nhưng khác → permanent failure, không overwrite

    Nhờ vậy một attempt lặp lại không nhân đôi tác động và không phá output lạ.

def write_output_idempotent(path, data):
    destination = Path(path)
    temp_path = destination.with_suffix(destination.suffix + ".tmp")

    try:
        if destination.is_symlink():
            raise PermanentItemError("Output không được là symbolic link")

        if temp_path.is_symlink():
            raise PermanentItemError("Temporary output không được là symbolic link")

        if destination.exists():
            existing = json.loads(destination.read_text(encoding="utf-8"))

            if existing == data:
                return "already_current"

            raise PermanentItemError(
                "Output đã tồn tại với nội dung khác"
            )

        if destination.parent.is_symlink():
            raise PermanentItemError("Output folder không được là symbolic link")

        text = json.dumps(data, ensure_ascii=False, indent=2, sort_keys=True)
        destination.parent.mkdir(parents=True, exist_ok=True)
        temp_path.write_text(text, encoding="utf-8")
        written = json.loads(temp_path.read_text(encoding="utf-8"))

        if written != data:
            raise PermanentItemError("Output verification không khớp")

        temp_path.replace(destination)

        final_data = json.loads(destination.read_text(encoding="utf-8"))

        if final_data != data:
            raise PermanentItemError("Final output verification không khớp")

        return "written"
    except PermanentItemError:
        raise
    except json.JSONDecodeError as error:
        raise PermanentItemError(
            "Output hiện có hoặc temporary output không phải JSON hợp lệ"
        ) from error
    except UnicodeDecodeError as error:
        raise PermanentItemError("Output hiện có không phải UTF-8 hợp lệ") from error
    except (PermissionError, OSError) as error:
        raise RetryableItemError("Không thể ghi output: " + str(error)) from error


def process_item(item):
    ensure_source_unchanged(item)
    data = read_json_dictionary(item.source)
    return write_output_idempotent(item.destination, data)

    def run_one_item(
    item,
    plan,
    active_manifest,
    logger,
    process_function,
    sleep_function,
):
    while item.attempts < plan.max_attempts:
        item.attempts = item.attempts + 1
        item.status = "processing"
        item.last_error = ""
        active_manifest.save_current()
        logger.info(
            "ATTEMPT_START | %s | attempt=%s/%s",
            item.source,
            item.attempts,
            plan.max_attempts,
        )

        try:
            result = process_function(item)
        except PermanentItemError as error:
            begin_quarantine(
                item,
                "Permanent failure: " + str(error),
                active_manifest,
                logger,
            )
            return
        except RetryableItemError as error:
            item.last_error = "Retryable failure: " + str(error)

            if item.attempts >= plan.max_attempts:
                begin_quarantine(
                    item,
                    "Retry exhausted: " + str(error),
                    active_manifest,
                    logger,
                )
                return

            item.status = "retryable_failed"
            active_manifest.save_current()
            calculated_delay = (
                plan.base_delay_seconds * (2 ** (item.attempts - 1))
            )
            delay = min(calculated_delay, MAX_RETRY_DELAY_SECONDS)
            logger.warning(
                "ATTEMPT_RETRY | %s | delay=%s | %s",
                item.source,
                delay,
                error,
            )
            sleep_function(delay)
            continue

        item.status = "succeeded"
        item.last_error = ""
        active_manifest.save_current()
        logger.info(
            "ITEM_SUCCEEDED | %s | attempt=%s | result=%s",
            item.source,
            item.attempts,
            result,
        )
        return

    manifest_store,
    logger,
    resume=False,
    process_function=process_item,
    sleep_function=time.sleep,
):
    if resume:
        validate_plan_for_resume(plan)
    else:
        validate_plan_for_start(plan)

    active_manifest = ActiveManifest(manifest_store, plan)

    if resume:
        reconcile_for_resume(plan, active_manifest, logger)
    else:
        active_manifest.save_current()

    logger.info(
        "BATCH_START | resume=%s | items=%s",
        resume,
        len(plan.items),
    )

    for item in plan.items:
        if item.status in {"succeeded", "quarantined"}:
            continue

        if item.status != "pending":
            raise BatchError(
                "Item còn status không thể chạy: "
                + item.status
                + " | "
                + item.source
            )

        run_one_item(
            item,
            plan,
            active_manifest,
            logger,
            process_function,
            sleep_function,
        )

    for item in plan.items:
        if item.status not in {"succeeded", "quarantined"}:
            raise BatchError(
                "Batch kết thúc loop nhưng item chưa terminal: "
                + item.source
            )

    logger.info("BATCH_COMPLETE")

    process_function và sleep_function là dependency injection bằng function object.

    Khi test, ta có thể truyền fake processor tạo lỗi tạm thời và fake sleep không thực sự chờ.

    🧠 28. Resume không đồng nghĩa chạy lại từ đầu

    Giả sử manifest:

    A succeeded, attempts=1
B processing, attempts=1
C quarantined, attempts=1

    A skip

C skip
D → pending nếu còn budget

    def run_and_report(plan, store, paths, logger, resume):
    try:
        run_batch(plan, store, logger, resume=resume)
        write_report(paths["state"] / "report.json", plan, "completed")
    except BatchError as error:

    succeeded = count_status(plan, "succeeded")
    quarantined = count_status(plan, "quarantined")
    print("Succeeded:", succeeded)
    print("Quarantined:", quarantined)
    print("Report:", paths["state"] / "report.json")

    if quarantined > 0:
        return 2

    return 0

    parser = build_parser()
    args = parser.parse_args()
    paths = make_paths(args.workspace)
    store = ManifestStore(paths["state"] / "manifest.json")

    try:
        if args.resume:
            plan = store.load()

            if Path(plan.workspace) != paths["workspace"]:
                raise BatchError(
                    "Manifest workspace không khớp CLI workspace"
                )

            print_plan(plan)
            answer = input("Gõ RESUME để tiếp tục batch: ")

            if answer != "RESUME":
                print("Đã hủy resume")
                return 0

            logger = build_logger(paths["state"] / "batch.log")
            return run_and_report(plan, store, paths, logger, resume=True)

        plan = build_plan(
            args.workspace,
            args.max_attempts,
            args.base_delay,
        )

            print("Plan có problem. Batch mới bị block.")
            return 2

            print("DRY-RUN: chưa tạo output, state hoặc quarantine")
            return 0

        answer = input("Gõ APPLY để bắt đầu batch: ")

        if answer != "APPLY":
            print("Đã hủy batch")
            return 0

        logger = build_logger(paths["state"] / "batch.log")
        return run_and_report(plan, store, paths, logger, resume=False)
    except (BatchError, TypeError, ValueError) as error:
        print("ERROR:", error)
        return 1

    🧠 33. Exit code của batch

    Project trả về:

    0  tất cả item succeeded hoặc user hủy trước khi chạy
1  infrastructure/batch failure làm workflow dừng
2  batch kết thúc nhưng có item quarantined, hoặc plan bị block

    “Batch complete” không nhất thiết nghĩa mọi item thành công. Summary và exit code phải nói rõ partial outcome.

    Bài 1 — delay table

    Viết build_retry_delays(max_attempts, base_delay) trả về các delay sẽ dùng. Không có delay sau attempt cuối.

    📌 39. Thuật ngữ quan trọng

    • batch — nhóm nhiều item được xử lý trong một workflow.
    • item isolation — cô lập lỗi của một item khỏi các item khác.
    • retryable failure — lỗi có khả năng thành công khi thử lại.
    • permanent failure — lỗi cần sửa input/policy trước khi có thể thành công.
    • retry budget — số attempt tối đa của một item.
    • exponential backoff — delay tăng theo cấp số nhân giữa các retry.
    • quarantine — trạng thái/vùng cô lập item cần điều tra.
    • resume — tiếp tục batch từ manifest đã lưu.
    • reconciliation — đối chiếu trạng thái dang dở để quyết định bước tiếp.
    • fingerprint — dữ liệu nhận diện trạng thái source tại thời điểm discovery.
    • idempotent output — ghi lại cùng kết quả không nhân đôi hoặc phá dữ liệu.
    • partial outcome — batch kết thúc với nhiều trạng thái item khác nhau.
    • dependency injection — truyền dependency từ ngoài để thay thế khi test.

    ✅ Điều cần nhớ

    Retry item, không retry mù quáng toàn batch.

    Chỉ retry lỗi có khả năng tạm thời và luôn có giới hạn.

    Permanent failure và retry exhausted đi quarantine.

    Checkpoint manifest trước và sau mỗi attempt.

    Resume dựa vào manifest membership, attempts và status.

    Operation idempotent là nền tảng để xử lý lại trạng thái processing.

    Hỏng infrastructure theo dõi thì phải dừng batch.
