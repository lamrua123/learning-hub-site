    Bài 045 — Type hints, dataclass và model dữ liệu

    🎯 Hôm nay học gì?

    Khi chương trình lớn hơn, một câu hỏi xuất hiện liên tục:

    Function này nhận dữ liệu gì và trả dữ liệu gì?

    Một câu hỏi khác:

    Object này chỉ giữ dữ liệu hay còn có nhiều lifecycle phức tạp?

    Hôm nay, chúng ta học hai công cụ giúp code trả lời rõ hơn:

    • type hints mô tả kiểu dữ liệu mong đợi;
    • dataclass giảm code lặp khi xây object chủ yếu dùng để giữ dữ liệu.

    Sau bài này, bạn có thể:

    • thêm type hints cho variable, parameter và return value;
    • mô tả list, dictionary, tuple, set và value có thể là None;
    • type-hint callback, iterable và generator;
    • hiểu type checker làm gì và không làm gì;
    • phân biệt type hint với runtime validation;
    • hiểu Any làm mất thông tin như thế nào;
    • dùng @dataclass;
    • hiểu __init__, __repr__ và __eq__ được tạo tự động;
    • dùng default value đúng cách;
    • dùng field(default_factory=...) cho collection mutable;
    • validation và normalize bằng __post_init__();
    • tạo model dữ liệu có invariant rõ;
    • chuyển dataclass thành dictionary;
    • biết khi nào dataclass phù hợp và khi nào class thường phù hợp hơn.

    Ranh giới kiến thức

    Bài này sử dụng cú pháp type hints hiện đại của Python:

    list[str]
dict[str, int]
str | None

    Cú pháp | cho union cần Python 3.10 trở lên.

    Chúng ta chưa đi sâu vào:

    • generic class tự định nghĩa;
    • TypeVar;
    • Protocol;
    • overload;
    • variance;
    • static checker configuration lớn;
    • schema library bên thứ ba;
    • ORM hoặc database model.

    Mục tiêu là type-safe vừa đủ cho app, game, automation và tool nhỏ.

    🧒 Hiểu cực đơn giản

    Hãy tưởng tượng mỗi function là một quầy nhận và trả hàng.

    Không có nhãn:

    đưa gì vào cũng được?
nhận gì ra không biết?

    Có type hints:

    nhận: tên dạng text + số lần retry dạng int
trả: một JobPlan

    Type hints giống nhãn trên hộp.

    Nhãn giúp:

    • người đọc hiểu;
    • editor gợi ý;
    • type checker phát hiện sự không khớp;
    • refactor an toàn hơn.

    Nhưng nhãn không phải nhân viên bảo vệ.

    Nếu runtime cần từ chối dữ liệu sai, ta vẫn phải validation.

    dataclass giống một mẫu hộp chuẩn: Python tự tạo phần lắp ráp lặp lại, còn ta định nghĩa field và quy tắc hợp lệ.

    🧠 1. Type hint là gì?

    Type hint là thông tin mô tả kiểu dữ liệu mà code mong đợi.

    Ví dụ:

    def greet(name: str) -> str:
    return "Xin chào " + name

    Ý nghĩa:

    • name: str: parameter name được mong đợi là string;
    • -> str: function được mong đợi trả string.

    Type hint giúp mô tả contract.

    🧩 2. Type hints cho parameters

    def calculate_damage(attack: int, defense: int) -> int:
    damage = attack - defense

    if damage < 0:
        return 0

    return damage


print(calculate_damage(20, 7))

    Người đọc thấy ngay:

    • hai inputs là int;
    • output là int.

    🧩 3. Type hint cho return value

    def is_ready(enabled: bool, retries: int) -> bool:
    return enabled and retries >= 0

    -> bool mô tả result.

    Function không trả meaningful value dùng -> None:

    def show_message(message: str) -> None:
    print(message)

    🧩 4. Type hint cho variable

    player_name: str = "An"
score: int = 100
speed: float = 4.5
is_alive: bool = True

    Variable annotation hữu ích khi:

    • value ban đầu chưa đủ rõ;
    • collection đang rỗng;
    • muốn ghi contract state;
    • tool cần biết kiểu dự kiến.

    Không cần annotate mọi biến trung gian hiển nhiên.

    count = 10

    Tool thường tự suy luận count là int.

    🧠 5. Type inference

    Type inference là việc công cụ suy ra kiểu từ code.

    name = "An"
score = 100

    Type checker thường suy ra:

    name: str
score: int

    Type hints nên thêm ở các boundary quan trọng:

    • function API;
    • class fields;
    • collection rỗng;
    • return type không rõ;
    • callback;
    • dữ liệu đi qua module.

    🧠 6. Type hints không tự ép kiểu lúc runtime

    def double(number: int) -> int:
    return number * 2


print(double("ha"))

    Python vẫn chạy và in:

    haha

    Type hint không tự chặn string.

    Nó không giống:

    • int(value) để convert;
    • isinstance() để kiểm tra runtime;
    • raise để từ chối input.

    🧠 7. Static checking và runtime

    Static type checking kiểm tra code mà không cần chạy mọi đường logic.

    Type checker có thể cảnh báo:

    Argument có type "str" nhưng parameter cần "int"

    Runtime là lúc Python thật sự chạy chương trình.

    So sánh:

    🧠 42. __post_init__()

    Dataclass gọi __post_init__() ngay sau constructor tự động gán fields.

    from dataclasses import dataclass


@dataclass
class Player:
    name: str
    level: int

    def __post_init__(self) -> None:
        if not isinstance(self.name, str):
            raise TypeError("name phải là string")

        self.name = self.name.strip()

        if self.name == "":
            raise ValueError("name không được trống")

        if isinstance(self.level, bool) or not isinstance(self.level, int):
            raise TypeError("level phải là int")

        if self.level < 1:
            raise ValueError("level phải từ 1")

    __post_init__() phù hợp để:

    • validation;
    • normalize fields;
    • tính derived field đơn giản;
    • bảo vệ invariants.

    🔍 43. Thứ tự khởi tạo dataclass

→ normalize name thành "An"

    🧠 55. Dataclass hay class thường?

    Yêu cầu:

    • input là Iterable[int];
    • output là Iterator[int];
    • chỉ yield 0–100;
    • runtime từ chối bool nếu input không đáng tin;
    • test list, tuple và generator input.

    📌 100. Thuật ngữ quan trọng

    Type hint

    Thông tin mô tả type mà code mong đợi.

    Type annotation

    Cú pháp gắn type information vào variable, parameter, return hoặc field.

    Static type checking

    Kiểm tra sự nhất quán kiểu bằng công cụ mà không cần chạy mọi đường logic.

    Runtime validation

    Kiểm tra dữ liệu khi chương trình đang chạy.

    Type inference

    Khả năng công cụ suy ra type từ code.

    Type narrowing

    Thu hẹp union/object thành type cụ thể sau kiểm tra.

    Union type

    Type cho phép value thuộc một trong nhiều types, viết bằng |.

    Optional value

    Value có thể là type chính hoặc None.

    Any

    Type đặc biệt cho phép type checker bỏ qua nhiều kiểm tra trên value.

    Type alias

    Tên có ý nghĩa được đặt cho một type expression.

    Callable

    Type mô tả callable cùng input/output contract.

    Iterable

    Type mô tả object có thể duyệt.

    Iterator

    Type mô tả iterator giao từng item.

    Data model — model dữ liệu

    Cấu trúc đại diện một khái niệm và contract dữ liệu trong chương trình.

    Boilerplate

    Code cấu trúc lặp lại không phải logic đặc biệt.

    Dataclass

    Class được @dataclass xử lý để tự tạo methods dựa trên annotated fields.

    field()

    Function cấu hình cách dataclass xử lý một field.

    Default factory

    Callable được gọi để tạo default mới cho mỗi instance.

    __post_init__()

    Method dataclass gọi sau khi constructor tự động gán fields.

    Invariant

    Điều kiện phải đúng với mọi state hợp lệ của model.

    Frozen dataclass

    Dataclass chặn việc gán lại fields sau construction.

    asdict()

    Function chuyển dataclass và nested dataclasses thành dictionaries.

    Business identity

    Quy tắc nghiệp vụ quyết định hai records có đại diện cùng thực thể hay không.

    Mutation policy

    Quy tắc về fields nào được thay đổi, thay đổi bằng cách nào và validation ra sao.

    ✅ 101. Điều cần nhớ

    1. Type hints mô tả contract cho người đọc và công cụ.
    2. Python không tự enforce hints lúc runtime.
    3. External input vẫn cần runtime validation và conversion.
    4. Static checking và tests giải quyết các loại rủi ro khác nhau.
    5. Annotate parameters và return types tại API boundaries.
    6. Collection hints mô tả cả container và item types.
    7. Union A | B nghĩa value có thể là một trong hai types.
    8. T | None làm optional result rõ ràng.
    9. Any làm type checker mất thông tin; dùng có chủ đích.
    10. object cộng narrowing giữ boundary thận trọng hơn.
    11. Callable mô tả callback contract.
    12. Dùng Iterable khi function chỉ cần duyệt input.
    13. Return hint phải đúng trên mọi đường chạy.
    14. Data model đại diện shape, rules và behavior của dữ liệu nghiệp vụ.
    15. @dataclass giảm boilerplate cho __init__, repr và equality.
    16. Dataclass annotations vẫn không tự runtime validate.
    17. Fields bắt buộc phải đứng trước fields có default.
    18. Mutable defaults dùng field(default_factory=...).
    19. Factory cần callable như list, không phải result list().
    20. __post_init__() phù hợp cho validation, normalization và invariants.
    21. Snapshot mutable input khi model không nên chia sẻ ownership.
    22. frozen=True không tự deep-freeze nested mutable objects.
    23. asdict() chuyển structure nhưng không tự bảo đảm JSON schema.
    24. Dataclass equality theo fields có thể khác business identity.
    25. Mutation sau construction có thể phá invariant nếu policy không được bảo vệ.
    26. Dùng dataclass cho data-centric object; dùng class thường cho lifecycle phức tạp.
