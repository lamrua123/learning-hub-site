    Bài 031 — Module API, namespace và standard library

    [!info] Vị trí trong khóa học Phần 12 — Modules & Packages
    Bài trước: [[11 - Error Handling Debugging/030 - Resilient Data Processor|030 — Mini-project: Resilient Data Processor]]
    Bài tiếp theo: 032 — Tách chương trình thành module riêng
    Checkpoint tiếp theo: sau Bài 035, phạm vi 031–035

    Bạn đã dùng nhiều modules từ standard library:

    • pathlib để làm việc với paths;
    • json để đọc/ghi JSON;
    • csv để đọc/ghi CSV.

    Tới đây, mục tiêu không còn là “nhớ thêm nhiều function”. Mục tiêu là biết cách tiếp cận một module mới:

    nhu cầu
↓
chọn module
↓
đọc namespace
↓
chọn API name
↓
đọc contract
↓
thử ví dụ nhỏ
↓
kiểm tra boundary / side effect / exception
↓
tích hợp vào chương trình

    Bài này dùng ba modules làm phòng thí nghiệm:

    random   → lựa chọn pseudo-random
datetime → ngày, thời điểm và khoảng thời gian
pathlib  → path và filesystem operations

    Mental model chính:

    module = hộp công cụ có namespace
API = những names và contracts ta dùng từ hộp đó
standard library = bộ công cụ đi kèm Python

    🎯 Hôm nay đạt được gì?

    Sau bài này, bạn có thể:

    • giải thích module, namespace và API liên hệ với nhau thế nào;
    • phân biệt module name với name nằm trong module;
    • đọc qualified name như random.choice và datetime.date;
    • chọn giữa import module, from module import name và alias;
    • hiểu name collision khi direct import;
    • dùng dir() để khám phá names;
    • dùng help() và documentation để đọc API contract;
    • phân biệt public-looking name với internal-looking name;
    • kiểm tra parameter, return value, side effect và expected exception;
    • chọn đúng API thay vì viết lại công cụ đã có;
    • dùng random.randint(), choice(), sample(), shuffle() và seed();
    • hiểu pseudo-random và reproducible run;
    • dùng datetime.date, datetime.timedelta và ISO date;
    • dùng lại pathlib.Path như một API có contract;
    • hoàn thành Standard Library Practice Planner;
    • debug lỗi import, collision, boundary và misunderstanding về return value.

    Bài chưa tạo module riêng, chưa dùng package bên ngoài, pip, virtual environment, class definition, f-string, comprehension, lambda, decorator hoặc type hint.

    1. Module không chỉ là một file để import

    Hiểu cực đơn giản:

    module
→ một đơn vị code có tên
→ chứa các names liên quan
→ cung cấp công cụ cho code khác dùng

    Ví dụ:

    import random

print(random.__name__)

    Kết quả:

    random

    Name random trong chương trình đang tham chiếu tới module đã import.

    Module này cung cấp các names như:

    random.randint
random.choice
random.sample
random.shuffle

    2. Namespace — vùng chứa names

    Không gian tên (namespace) là vùng ánh xạ names tới values.

    Sau:

    import random

    namespace hiện tại có name:

    random

    Namespace của module random có các names:

    randint
choice
sample
shuffle
...

    Ta truy cập name bên trong module bằng dấu chấm:

    import random

number = random.randint(1, 6)
print(number)

    random.randint là tên có định danh nguồn (qualified name).

    Nó nói rõ:

    randint đến từ namespace random

    3. API là gì?

    Giao diện lập trình ứng dụng (Application Programming Interface — API) là phần giao tiếp được cung cấp để code khác sử dụng.

    Trong bài này, một API name có contract:

    name dùng để làm gì?
nhận parameters nào?
return value là gì?
có mutation/side effect không?
có thể raise exception nào?
boundary cases là gì?

    Ví dụ contract ngắn:

    random.randint(a, b)

purpose:
    chọn một integer pseudo-random

input:
    a và b là hai boundaries

return:
    một integer từ a đến b, tính cả hai đầu

side effect:
    làm state của random generator tiến lên

expected issue:
    range không hợp lệ có thể raise ValueError

    Biết tên function chưa đủ. Cần biết contract.

    4. Standard library — thư viện chuẩn

    Thư viện chuẩn (standard library) là tập hợp modules đi kèm Python.

    Các modules đã dùng:

    Module Nhu cầu
    pathlib path và filesystem
    json JSON serialization/parsing
    csv CSV parsing/writing
    random pseudo-random selection
    datetime date/time/duration

    Các module này không cần cài bằng pip.

    Điều đó không có nghĩa mọi thư viện Python đều thuộc standard library. Bài 033 mới học package bên ngoài và pip.

    5. import module — giữ nguồn gốc rõ

    import random

roll = random.randint(1, 6)

    Name trong scope hiện tại:

    random

    Name được gọi:

    random.randint

    Ưu điểm:

    • nhìn code biết randint đến từ đâu;
    • ít name collision;
    • tốt khi dùng nhiều names từ cùng module.

    Đây thường là lựa chọn dễ đọc cho beginner.

    6. from module import name — direct import

    from pathlib import Path

report_path = Path("report.txt")
print(report_path.name)

    Name Path được đưa trực tiếp vào namespace hiện tại.

    Ta gọi:

    Path(...)

    thay vì:

    pathlib.Path(...)

    Direct import phù hợp khi:

    • name rất rõ;
    • chỉ cần một vài names;
    • nguy cơ collision thấp;
    • style này làm code dễ đọc hơn.

    7. Alias — bí danh import

    Bí danh (alias) là name khác dùng trong file hiện tại.

    import datetime as dt

start_date = dt.date(2026, 8, 29)
print(start_date)

    Kết quả:

    2026-08-29

    Alias hữu ích khi module name dài hoặc có convention rất rõ.

    Nhưng alias phải dễ hiểu:

    dt → có thể hiểu là datetime trong context phù hợp
x  → gần như không nói gì

    Không dùng alias chỉ để tiết kiệm vài ký tự.

    8. Name collision — hai nguồn muốn cùng một name

    from random import choice


def choice(options):
    return options[0]

    Function tự định nghĩa đã gán lại name choice. Direct-imported random.choice không còn được truy cập qua name đó.

    Qualified import tránh collision:

    import random


def choice(options):
    return options[0]


print(choice(["A", "B"]))
print(random.choice(["A", "B"]))

    Hai names có nguồn rõ ràng.

    9. Vì sao tránh wildcard import?

    Không dùng:

    from random import *

    Wildcard import đưa nhiều names vào scope hiện tại:

    • khó biết name đến từ đâu;
    • khó thấy collision;
    • dependency bị che;
    • đọc code khó hơn;
    • module thay đổi có thể ảnh hưởng namespace.

    Explicit import giúp dependency nhìn thấy được.

    10. Khám phá namespace bằng dir()

    dir(value) trả list names liên quan tới value đó.

    import random

names = dir(random)
print("choice" in names)
print("sample" in names)
print("not_a_real_name" in names)

    Kết quả:

    True
True
False

    Muốn xem public-looking names:

    import random

for name in dir(random):
    if not name.startswith("_"):
        print(name)

    dir() giúp khám phá. Nó không thay thế documentation vì list names không nói đủ contract.

    11. Dấu gạch dưới và internal-looking names

    Names bắt đầu bằng _ thường được xem là implementation detail hoặc không dành cho use thông thường:

    _something
__something__

    Không phải mọi name có underscore đều “cấm”, nhưng beginner nên ưu tiên documented public API.

    Ví dụ __name__ là special attribute được dùng có chủ đích để quan sát module name. Không suy ra rằng mọi __...__ đều nên gọi trực tiếp.

    12. Dùng help() để đọc contract

    Trong Python shell, có thể gọi:

    import random

help(random.randint)

    Help thường cho biết:

    • name;
    • cách gọi;
    • mô tả;
    • parameters;
    • return behavior.

    Với module:

    help(random)

    output có thể rất dài. Khi đã biết name cần dùng, hỏi help cho đúng name thường tập trung hơn.

    Nhấn q nếu terminal pager đang hiển thị help dài và bạn muốn thoát.

    13. Documentation không chỉ là danh sách functions

    Khi đọc tài liệu một API, ghi một API card:

    Qualified name:
Purpose:
Parameters:
Return value:
Side effect / mutation:
Expected exceptions:
Boundary cases:
Small example:

    Ví dụ:

    Qualified name: random.shuffle
Purpose: đổi thứ tự list tại chỗ
Parameters: list cần shuffle
Return value: None
Side effect: mutation list gốc
Boundary: list rỗng vẫn hợp lệ

    API card ngăn hai bug phổ biến:

    • đoán sai return value;
    • bỏ sót mutation.

    14. Quy trình chọn API

    1. Viết nhu cầu bằng một câu.
2. Xác định module có trách nhiệm gần nhất.
3. Tìm public API name phù hợp.
4. Đọc contract.
5. Viết ví dụ nhỏ nhất.
6. Thử boundary case.
7. Kiểm tra return value và mutation.
8. Tích hợp sau khi hiểu hành vi.

    Ví dụ nhu cầu:

    “Chọn ba quests khác nhau mà không sửa list gốc.”

    So sánh:

    API Phù hợp? Lý do
    random.choice() chưa đủ chỉ chọn một item mỗi call
    random.shuffle() không mutation list gốc
    random.sample() có chọn nhiều item không trùng, trả list mới

    15. random tạo pseudo-random values

    Giá trị từ module random là giả ngẫu nhiên (pseudo-random):

def run_planner(root, quest_bank, quest_count, seed_value, start_date_text, spacing_days):
    output_folder = root / "output"
    output_path = output_folder / "practice_plan.txt"

    if not paths_are_safe(root, output_folder, output_path):
        return {"status": "blocked_path", "issues": ["Path contract không hợp lệ"]}

    bank_issues = validate_quest_bank(quest_bank)

    if len(bank_issues) > 0:
        return {"status": "blocked_data", "issues": bank_issues}

    selection_result = select_quests(quest_bank, quest_count, seed_value)

    if not selection_result["ok"]:
        return {"status": "blocked_selection", "issues": [selection_result["message"]]}

    schedule_result = schedule_quests(
        selection_result["selected"],
        start_date_text,
        spacing_days
    )

    if not schedule_result["ok"]:
        return {"status": "blocked_schedule", "issues": [schedule_result["message"]]}

    report = build_plan_report(
        schedule_result["schedule"],
        seed_value,
        start_date_text,
        spacing_days
    )

    output_folder.mkdir(parents=True, exist_ok=True)
    output_path.write_text(report, encoding="utf-8")
    saved_report = output_path.read_text(encoding="utf-8")

    return {
        "status": "built",
        "issues": [],
        "schedule": schedule_result["schedule"],
        "report": report,
        "output_path": output_path,
        "read_back_matches": saved_report == report
    }

    47. 🐛 Bug Lab

    Quy trình:

    quan sát symptom
→ xác định module/API
→ đọc contract
→ tạo example nhỏ
→ sửa
→ chạy boundary case

    Bug 1 — quên module prefix

    import random
roll = randint(1, 6)

    Symptom: NameError.

    Gợi ý: namespace hiện tại có random, không có direct name randint.

    Bug 2 — module bị rebinding

    import random
random = 10
roll = random.randint(1, 6)

    Symptom: integer không có attribute randint.

    Gợi ý: name random đang trỏ tới value nào tại thời điểm call?

    Bug 3 — alias gọi sai

    import datetime as dt
day = datetime.date.today()

    Symptom: NameError nếu datetime chưa được import bằng name đó.

    Gợi ý: alias nào thật sự nằm trong scope?

    Bug 4 — randint và range mental model bị trộn

    Coder nghĩ randint(1, 6) chỉ trả 1–5.

    Gợi ý: đọc boundary contract, test nhiều lần với seed chỉ để quan sát.

    Bug 5 — sample quá lớn

    random.sample(["A", "B"], 3)

    Symptom: ValueError.

    Gợi ý: validate k với population length.

    Bug 6 — shuffle làm list thành None

    items = random.shuffle(items)

    Symptom: items trở thành None.

    Gợi ý: return value và mutation contract.

    Bug 7 — shuffle phá source

    Project cần giữ quest bank, nhưng gọi random.shuffle(quest_bank).

    Gợi ý: copy trước mutation hoặc chọn sample().

    Bug 8 — seed lại trong loop

    for turn in range(3):
    random.seed(10)
    print(random.randint(1, 6))

    Symptom: cùng một roll lặp lại.

    Gợi ý: seed một lần tại boundary.

    Bug 9 — tự cộng day

    day = 30
day = day + 5

    Symptom: tạo “ngày 35”.

    Gợi ý: dùng date + timedelta.

    Bug 10 — parse impossible date

    Code catch TypeError nhưng input "2026-02-30" raise ValueError.

    Gợi ý: test exact exception type.

    Bug 11 — Path bị hiểu là file thật

    path = Path("output/report.txt")
print(path.read_text())

    Symptom: FileNotFoundError.

    Gợi ý: tạo Path không tạo file hoặc parent folder.

    Bug 12 — writer chạy trước path guard

    mkdir() xảy ra rồi mới kiểm tra exact root.

    Gợi ý: validation phải đứng trước filesystem side effect.

    Bug 13 — dùng dir() như documentation đầy đủ

    Coder thấy shuffle nhưng đoán nó return list mới.

    Gợi ý: dir() chỉ cho names; đọc help()/contract.

    Bug 14 — wildcard collision

    Một imported name bị function/local data ghi đè nhưng không rõ nguồn.

    Gợi ý: explicit qualified import.

    Thuật ngữ Nghĩa dễ hiểu
    module đơn vị code có tên chứa các names liên quan
    namespace vùng ánh xạ names tới values
    API phần giao tiếp và contract cho code khác sử dụng
    public API names được module cung cấp để dùng thông thường
    qualified name name kèm namespace nguồn như random.choice
    direct import đưa một name từ module vào scope hiện tại
    alias bí danh được dùng cho imported module/name
    name collision hai nguồn dùng cùng name trong một namespace
    wildcard import import nhiều names bằng * làm nguồn gốc khó thấy
    standard library tập modules đi kèm Python
    third-party package code package bên ngoài Python standard library
    API contract purpose, inputs, return, side effect, errors và boundaries
    return value value API gửi lại cho caller
    side effect thay đổi ngoài return value, như mutation hoặc ghi file
    internal-looking name name bắt đầu _, thường không phải public API thông thường
    pseudo-random values sinh bởi algorithm/state nhưng trông ngẫu nhiên
    seed giá trị khởi tạo random state để hỗ trợ tái hiện sequence
    population collection nguồn mà random API chọn từ đó

    ngày ISO ISO date
    khoảng thời gian duration / timedelta
    API card ghi chú ngắn về contract của một API name

    52. ✅ Điều cần nhớ

    1. Module là namespace có tên; API là phần ta dùng từ namespace đó.

2. Qualified name giữ nguồn gốc rõ và giảm collision.

3. dir() cho names; help/documentation cho contract.

4. Đọc parameters, return, side effect, exceptions và boundaries.

5. Chọn API theo requirement, không theo tên có vẻ quen.

6. randint tính cả hai đầu; range không tính stop.

7. choice chọn một; sample chọn nhiều không trùng;
   shuffle mutation list và return None.

8. Seed hỗ trợ reproducible debugging, không tạo security randomness.

9. date biểu diễn ngày; timedelta biểu diễn khoảng thời gian.

10. Dùng calendar API thay vì tự cộng day/month.

11. Tạo Path value không tạo file; đọc contract trước filesystem side effect.

12. Import và dùng module có sẵn là bước chuẩn bị để Bài 032 tự tách code thành modules riêng.

    Bạn đã chuyển từ “biết cú pháp import” sang “biết đọc và chọn API”. Bài 032 sẽ dùng mental model namespace/API này để tách chương trình của chính bạn thành nhiều modules có responsibility rõ ràng.
