    Bài 036 — Constructor và trạng thái hợp lệ

    [!info] Vị trí trong khóa học Phần 13 — OOP
    Bài trước: [[13 - OOP/035 - Class object attribute va method|035 — Class, object, attribute và method]]
    Bài tiếp theo: 037 — Composition: ghép object thành hệ thống
    Checkpoint tiếp theo: sau Bài 040, phạm vi 036–040

    Bài 035 cố ý tạo object theo ba bước:

    class Robot:
    def show_status(self):
        print(self.name, self.energy)


robot = Robot()
robot.name = "Alpha"
robot.energy = 80

    Cách đó giúp ta nhìn rõ object và attribute, nhưng có một lỗ hổng:

    broken_robot = Robot()
broken_robot.name = "Broken"

broken_robot.show_status()

    Object đã tồn tại nhưng thiếu energy.

    Ta muốn thay đổi contract:

    Robot hợp lệ
→ phải có name
→ phải có energy trong range
→ phải có durability trong range
→ mọi attribute ban đầu được thiết lập cùng lúc

    Python cung cấp special method __init__ để thiết lập trạng thái ban đầu (initial state) ngay trong quá trình tạo object.

    Mental model chính:

    ClassName(arguments)
↓
Python tạo object mới
↓
Python gọi __init__(object_mới, arguments)
↓
__init__ kiểm tra và gắn initial attributes
↓
caller nhận object đã được khởi tạo

    [!important] Cách gọi thuật ngữ cho chính xác Trong thực hành beginner, __init__ thường được gọi là constructor.
    Chính xác hơn, ClassName(...) bắt đầu quá trình tạo object, còn __init__ là initializer thiết lập object sau khi object đã được tạo.
    Bài này dùng cụm “constructor __init__” theo cách gọi phổ biến, đồng thời giữ mental model kỹ thuật ở trên.

    🎯 Hôm nay học gì?

    Sau bài này, bạn có thể:

    • giải thích vấn đề object sinh ra thiếu attributes;
    • định nghĩa __init__ với self và các parameters;
    • truyền arguments khi gọi class;
    • gắn mọi instance attribute ban đầu qua self;
    • lần theo object-creation flow;
    • dùng required và default constructor parameters;
    • normalize dữ liệu khởi tạo có chủ đích;
    • validate type, empty text, range và cross-field rule;
    • dùng TypeError và ValueError cho invalid construction;
    • validation trước assignment để constructor dễ đọc;
    • viết và kiểm tra object invariants;
    • phân biệt constructor failure với action rejection;
    • hiểu vì sao __init__ không return object;
    • tránh I/O và workflow nặng trong constructor;
    • chuyển factory function tạm thời của Bài 035 thành constructor;
    • hoàn thành project Validated Automation Job Queue.

    Bài chưa học composition giữa nhiều loại objects, inheritance, override, property, dataclass, type hint hoặc class method.

    1. 🧒 Hiểu cực đơn giản — phiếu xuất xưởng

    Hãy tưởng tượng robot rời xưởng.

    Một robot không thể được giao nếu thiếu:

    • serial number;
    • năng lượng ban đầu;
    • độ bền ban đầu.

    Phiếu xuất xưởng kiểm tra dữ liệu rồi thiết lập robot:

    nhận dữ liệu đặt hàng
↓
kiểm tra đủ và hợp lệ
↓
gắn dữ liệu vào robot
↓
robot sẵn sàng sử dụng

    __init__ đóng vai trò tương tự cho object.

    Không có constructor rõ:

    tạo object rỗng
↓
hy vọng caller nhớ gắn từng attribute

    Có constructor rõ:

    caller phải cung cấp dữ liệu bắt buộc
↓
constructor thiết lập attributes nhất quán
↓
method có thể dựa vào initial-state contract

    2. Constructor đầu tiên

    class Player:
    def __init__(self, name, hp):
        self.name = name
        self.hp = hp

    Tạo object:

    hero = Player("An", 100)

print(hero.name)
print(hero.hp)

    Kết quả:

    An
100

    Ta không còn viết:

    hero = Player()
hero.name = "An"
hero.hp = 100

    Hai attributes bắt buộc được thiết lập trong cùng một construction flow.

    3. Cú pháp __init__

    class ClassName:
    def __init__(self, parameter_one, parameter_two):
        self.attribute_one = parameter_one
        self.attribute_two = parameter_two

    Các phần:

    Phần Vai trò
    def định nghĩa method
    __init__ special method được gọi trong construction flow
    self object mới đang được thiết lập
    parameters còn lại nhận constructor arguments từ caller
    self.attribute = value tạo initial instance attribute

    Hai dấu gạch dưới mỗi bên trong __init__ là một phần của exact name:

    __init__

    Không phải:

    _init_
init
__int__

    4. self trong constructor vẫn là object hiện tại

    self ở Bài 035 không đổi ý nghĩa.

    class Player:
    def __init__(self, name, hp):
        self.name = name
        self.hp = hp

    def show_status(self):
        print(self.name, "- HP:", self.hp)

    Khi gọi:

    hero = Player("An", 100)
hero.show_status()

    Mental model:

    Player("An", 100)
↓
self là object Player mới
name nhận "An"
hp nhận 100
↓
self.name = "An"
self.hp = 100
↓
object được gán vào hero

    Sau đó hero.show_status() lại truyền chính hero vào self của method đó.

    5. Parameters không phải attributes

    Xem constructor:

    class Player:
    def __init__(self, name, hp):
        self.name = name
        self.hp = hp
    Name Loại
    name parameter của lần gọi __init__
    hp parameter của lần gọi __init__
    self.name attribute sống trên object
    self.hp attribute sống trên object

    Sau constructor:

    • parameters kết thúc vai trò của lần gọi;
    • attributes vẫn thuộc object;
    • methods khác đọc self.name và self.hp.

    Sai:

    class Player:
    def __init__(self, name, hp):
        name = name
        hp = hp

    Code chỉ gán local parameters cho chính chúng. Object không nhận attributes.

    6. Constructor arguments được ghép theo parameters

    class Pet:
    def __init__(self, name, species, hunger):
        self.name = name
        self.species = species
        self.hunger = hunger

    Positional arguments:

    pet = Pet("Milo", "cat", 30)

    Mapping:

    self    ← object Pet mới, Python tự truyền
name    ← "Milo"
species ← "cat"
hunger  ← 30

    Caller không truyền argument cho self.

    Nếu thiếu argument:

    pet = Pet("Milo", "cat")

    Python báo TypeError vì constructor call không khớp signature.

    7. Keyword arguments giúp call rõ hơn

    Keyword arguments đã được dùng với các APIs như encoding="utf-8".

    Ta cũng có thể dùng chúng khi tạo object:

    class StudyTask:
    def __init__(self, title, minutes, priority):
        self.title = title
        self.minutes = minutes
        self.priority = priority


task = StudyTask(
    title="Ôn constructor",
    minutes=45,
    priority=2
)

    Lợi ích:

    • call tự mô tả;
    • ít nhầm các arguments có cùng type;
    • order của keyword arguments rõ theo name.

    Đừng truyền một keyword không tồn tại:

    task = StudyTask(title="Ôn", duration=45, priority=2)

    duration không khớp parameter minutes, nên xảy ra TypeError.

    8. Default constructor parameter

    Parameter mặc định phù hợp cho initial value thực sự có default rõ:

    class StudyTask:
    def __init__(self, title, minutes, priority=3):
        self.title = title
        self.minutes = minutes
        self.priority = priority

    Hai calls:

    normal_task = StudyTask("Đọc bài", 30)
urgent_task = StudyTask("Sửa bug", 45, priority=1)

print(normal_task.priority)
print(urgent_task.priority)

    Kết quả:

    3
1

    Default không có nghĩa caller được phép truyền value bất kỳ. Constructor vẫn cần validation.

    9. Initial state — trạng thái ban đầu

    Initial state là state ngay sau khi construction thành công.

    class StudyTask:
    def __init__(self, title, minutes):
        self.title = title
        self.minutes = minutes
        self.status = "todo"
        self.minutes_done = 0

    Caller cung cấp:

    title
minutes

    Class quyết định defaults thuộc domain:

    status = "todo"
minutes_done = 0

    Không cần bắt caller truyền dữ liệu mà mọi object mới luôn có cùng giá trị hợp lý.

    10. Required input và derived/default state

    Phân loại constructor data:

    Required input

    Caller phải cung cấp vì class không thể tự đoán:

    task title
estimated minutes
player name
starting HP nếu game cho phép nhiều mức

    Default state

    Class có một initial value rõ:

    new task status = todo
attempts = 0
last_error = ""

    Derived state

    Value được tính từ input khác:

    class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

        if type(source_name) != str:
            raise TypeError("source_name phải là string")

        if type(target_name) != str:
            raise TypeError("target_name phải là string")

        if type(priority) != int:
            raise TypeError("priority phải là integer")

        clean_job_id = job_id.strip()
        clean_source = source_name.strip()
        clean_target = target_name.strip()

        if clean_job_id == "":
            raise ValueError("job_id không được rỗng")

        if clean_source == "":
            raise ValueError("source_name không được rỗng")

        if clean_target == "":
            raise ValueError("target_name không được rỗng")

        if clean_source == clean_target:
            raise ValueError("source_name và target_name phải khác nhau")

        if priority < 1 or priority > 5:
            raise ValueError("priority phải từ 1 đến 5")

        self.job_id = clean_job_id
        self.source_name = clean_source
        self.target_name = clean_target
        self.priority = priority
        self.status = "planned"
        self.attempts = 0
        self.last_error = ""

    def start(self):
        if self.status != "planned":
            return {
                "ok": False,
                "message": self.job_id + " cannot start from " + self.status
            }

        self.status = "running"
        self.attempts = self.attempts + 1

        return {
            "ok": True,
            "message": self.job_id + " started"
        }

    def complete(self):
        if self.status != "running":
            return {
                "ok": False,
                "message": self.job_id + " cannot complete from " + self.status
            }

        self.status = "completed"
        self.last_error = ""

        return {
            "ok": True,
            "message": self.job_id + " completed"
        }

    def fail(self, error_message):
        if type(error_message) != str or error_message.strip() == "":
            return {
                "ok": False,
                "message": "error_message không hợp lệ"
            }

        if self.status != "running":
            return {
                "ok": False,
                "message": self.job_id + " cannot fail from " + self.status
            }

        self.status = "failed"
        self.last_error = error_message.strip()

        return {
            "ok": True,
            "message": self.job_id + " failed: " + self.last_error
        }

    def retry(self):
        if self.status != "failed":
            return {
                "ok": False,
                "message": self.job_id + " cannot retry from " + self.status
            }

        self.status = "planned"
        self.last_error = ""

        return {
            "ok": True,
            "message": self.job_id + " planned for retry"
        }

    def is_finished(self):
        return self.status == "completed"

    def status_line(self):
        line = (
            self.job_id
            + " | " + self.source_name + " -> " + self.target_name
            + " | priority=" + str(self.priority)
            + " | status=" + self.status
            + " | attempts=" + str(self.attempts)
        )

        if self.last_error != "":
            line = line + " | error=" + self.last_error

        return line

    valid state state thỏa mọi invariant của class
    invariant rule phải đúng sau construction và mọi action hợp lệ
    type validation kiểm tra value có đúng data type contract
    value validation kiểm tra value đúng type có nằm trong rules/range
    cross-field validation rule cần so sánh nhiều input fields
    normalized value value đã được đưa về representation thống nhất theo contract
    construction failure failure khiến caller không nhận object hợp lệ
    action rejection object hợp lệ nhưng action không được phép trong state hiện tại
    ownership contract quy ước object giữ shared reference hay copy input mutable data
    mutable default mutable value được tạo ở definition và có thể bị nhiều calls chia sẻ
    sentinel None value đặc biệt báo constructor cần tự tạo mutable default mới

    56. ✅ Điều cần nhớ

    1. Gọi ClassName(arguments) bắt đầu construction flow cho một object mới.

2. __init__ thiết lập initial state và thường được gọi là constructor trong thực hành.

3. self là object mới; caller không truyền argument cho self.

4. Constructor parameters nhận input; self.attributes giữ state sau construction.

5. Mọi required instance attribute nên được thiết lập nhất quán trong __init__.

6. Phân loại required input, class-controlled defaults và derived state.

7. Validate type, normalize, validate value/cross-field rules rồi mới assign.

8. Type sai dùng TypeError; type đúng nhưng value sai dùng ValueError theo contract bài.

9. Constructor tạo initial invariant; methods duy trì invariant qua state changes.

10. Invalid construction khác object hợp lệ nhưng action bị từ chối.

11. __init__ không return object; Python construction machinery làm việc đó.

12. Catch constructor exception chỉ ở boundary có recovery/reporting policy.

13. Không trộn input/file/network workflow vào constructor.

14. Với mutable input, ghi rõ shared-reference hay copy ownership contract.

15. Không dùng mutable default trực tiếp; dùng None sentinel để tạo value mới mỗi call.

16. Constructor không ngăn direct attribute mutation; caller vẫn phải tôn trọng public API.
